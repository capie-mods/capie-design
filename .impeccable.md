## Design Context

### Users

HOI4 players who rename things during a campaign. The mod has to be easy for Workshop
subscribers to install and use; every extra installation step loses players. The core task:
give your own country, its leader or another character, and its parties a name of your own,
typed where you already look at that object. States and cities are in scope too.

### Brand Personality

Native, legible, discreet. The interface fits HOI4 and leaves no doubt about which object will be
renamed. This comes from the product requirement to edit names the way divisions, armies and
fleets are renamed, not from a separate brand identity.

No global floating button. An earlier floating "Rename" button covered the leader's portrait or
the decisions, so it must not come back as an overlay on top of panels. The main editing happens
next to the object; entry points to the other features get a fixed place in the native interface
without covering its controls.

### Aesthetic Direction

In-place editing, as the game does for divisions, armies and fleets (CK3 was the first
reference). Clicking a name, or a discreet button next to it, opens an ordinary text field by the
object, with Apply and Cancel. The game's own fonts, colours, frames and control behaviour are
kept. A large on-screen keyboard is not the main way to edit; it remains only as the fallback of
the scripted editor when CAPIE is missing.

The full visual system is in [docs/design/DESIGN-SYSTEM.md](docs/design/DESIGN-SYSTEM.md) and
[docs/design/tokens.json](docs/design/tokens.json).

### Design Principles

1. Edit the object in its existing context; the target's name must be unambiguous.
2. Use the visual language of base HOI4 and its ordinary text field.
3. Apply saves the change; Cancel keeps the current name.
4. Who may edit, and when, follows from the player's own objects and the game rules.
5. Show real limits plainly. Never claim native typing or multiplayer sync because a field looks
   right; only an in-game test shows that.
